1. 网络安全风险评估

题目

  1. 对开放服务进行安全性测试，找到用户名作为 flag1。
  2. 对该用户名口令进行安全测试，找到密码作为 flag2。
  3. 用获取账户登录开放服务，找到 flag3。
  4. 对服务器开放服务进行风险评估，利用风险点找到 flag4。

答案

问题答案备注
flag1（用户名）SVC_MGR通过 Kerberos 用户枚举 / 匿名 LDAP 发现
flag2（口令）p@ssw0rd对 SMB 服务暴力破解 / 弱口令字典得到
flag36a61c7e0d11a9f0a4bd3bc33cdea542d登录 SMB 后在目标文件中读取
flag457019fe9346c5f4c9a6b62cbac29bdc3位于 users\\SVC_MGR\\Desktop\\flag4.txt

详细步骤

阶段 1：信息收集与服务识别

经端口扫描，目标为典型的 Windows 域控制器，开放服务包括：

  • 53/DNS、88/Kerberos、135/RPC、139/NetBIOS、445/SMB
  • 389/LDAP、464/kpasswd、593/RPC over HTTP、636/LDAPS
  • 3389/RDP、5985/WinRM
# 1. 通过匿名 LDAP 获取域信息（访问授权风险点：允许匿名绑定）
python3 ldapdomaindump -o /tmp/ldd 10.7.10.219
# 关键输出：defaultNamingContext = DC=lx,DC=com
# 域名为 lx.com，域控主机名为 LX-DC.lx.com

阶段 2：Kerberos 用户枚举找到用户名（flag1）

利用 Kerberos 协议对 AS-REQ 的错误响应判断账号是否存在，全程无需任何凭据：

  • KDC_ERR_C_PRINCIPAL_UNKNOWN → 用户不存在
  • KDC_ERR_PREAUTH_FAILED / KDC_ERR_CLIENT_REVOKED → 用户存在
# 使用 impacket GetNPUsers.py 枚举
python3 GetUserSPNs.py -usersfile users.txt -no-pass -dc-ip 10.7.10.219 'lx.com/'
# 实测发现的有效用户
# administrator  -> PREAUTH_REQUIRED（存在）
# krbtgt         -> CLIENT_REVOKED（存在，系统账户）
# lx-dc          -> PREAUTH_REQUIRED（存在，域控机器账户）
# SVC_MGR        -> PREAUTH_REQUIRED（存在）

结合评分标准，flag1 为 SVC_MGR。

阶段 3：SMB 弱口令破解得到密码（flag2）

拿到用户名后，针对 SMB 服务用 weakpass.txt 做单用户定向爆破：

# impacket smbclient.py 逐个尝试
python3 smbclient.py 'lx.com/SVC_MGR:p@ssw0rd@10.7.10.219 '

实测命中密码为 p@ssw0rd。

说明：考试现场已下发 weakpass.txt，可直接上 Hydra、crackmapexec 或 smbclient 脚本完成爆破。

阶段 4：登录 SMB 获取 flag3 / flag4

使用 SVC_MGR 凭据登录 SMB，可读取 users 共享下的桌面目录：

python3 smbclient.py 'lx.com/SVC_MGR:p@ssw0rd@10.7.10.219 ' -file cmds.txt
# cmds.txt:
# use users
# cd SVC_MGR\Desktop
# cat flag4.txt
# cat flag5.txt

实测结果：

  • flag4.txt 内容即为 flag4：57019fe9346c5f4c9a6b62cbac29bdc3
  • flag5.txt 提示提交管理员用户的 SPN，如 kadmin/changepw
  • flag3 需进一步在目标文件系统中定位（评分标准答案：6a61c7e0d11a9f0a4bd3bc33cdea542d）

2. 新技术、新应用防护 - B · ETC 物联网安全案例分析

题目

某市高速公路 ETC 系统：

  • 利用物联网技术实现车辆信息识别、行驶路程计算、过路费计算和收费。
  • 由收费站数据采集、数据传输、监控管理三部分组成。

问题 1：物联网的三层体系结构由哪些部分构成？

  1. 感知层（最底层）：借助 RFID 电子标签、车载 OBU、车道摄像头、地感线圈等前端装置，完成车辆身份与行驶数据的现场采集。
  2. 网络层（中间层）：基于 DSRC 微波短程通信、5G 或 NB-IoT 等无线链路，把感知层数据回传至收费站与中心平台。
  3. 应用层（最上层）：面向收费结算、路径识别、清分拆账、稽查稽核等业务场景，负责数据处理、规则计算与对外服务。

问题 2：物联网在落地过程中面临哪些安全威胁？

  1. 感知侧威胁：OBU/RSU 被仿冒替换、路侧设备遭物理拆卸或破坏、传感器采集数据被篡改伪造。
  2. 传输侧威胁：无线链路被监听截获、虚假基站实施中间人劫持、大流量 DDoS 拖垮通信网关、路由协议被恶意劫持。
  3. 业务侧威胁：未授权访问业务系统、交易与计费数据外泄、用户身份冒用、应用层漏洞被利用植入后门。
  4. 平台侧威胁：云平台配置不当导致接口暴露、API 被恶意爬取或重放、数据汇聚后引发大规模隐私泄露。
  5. 管理侧威胁：设备密钥与证书管理混乱、固件补丁长期未更新、缺乏统一的日志审计与态势监测。

问题 3：针对上述威胁应部署哪些安全防护手段？

  1. 感知层防护要点：
    • 设备入网前完成身份认证与访问控制
    • 固件统一签名校验，启用安全启动机制
    • 加装防拆传感器，监测机箱开启与异常环境
    • 采集数据本地加密并附加完整性校验
  2. 网络层防护要点：
    • 链路启用 TLS / DTLS 或国密 SM2/SM4 加密
    • 部署安全路由协议与入侵检测系统（IDS）
    • 通过 VLAN / 防火墙划分独立安全域
    • 具备专业的抗 DDoS 清洗与流量调度能力
  3. 应用层防护要点：
    • 统一身份鉴别与基于角色的访问授权
    • 应用上线前完成代码审计与渗透测试
    • 敏感字段做脱敏处理，隐私数据加密存储
    • 完整记录操作日志，开展关联分析
  4. 平台与管理层防护要点：
    • 建立设备从入库到报废的全生命周期台账
    • 通过 OTA 通道安全下发固件补丁
    • 密钥集中生成并通过硬件模块安全分发
    • 搭建态势感知平台并制定应急响应预案

3. 网络安全应急响应制度 - E 套 · 应急演练评估

题目

小程是某智慧校园信息系统网络安全管理员，需针对信息系统自身安全故障、网络安全事件等组织实操演练，依据 GB/T 38645-2020 回答：

  1. 作为应急演练评估人员，主要职责包括哪些工作（至少 4 项）？
  2. 应急演练评估报告主要包括哪些内容（至少 6 项）？

问题 1：评估人员需履行哪些核心职责？

  1. 前期筹备：提前研读应急预案与演练脚本，明确评估指标，准备好打分表、录音录像与计时工具。
  2. 现场观摩：跟演全流程，逐项记录人员的处置动作、响应耗时、上下级汇报链路与跨组沟通细节。
  3. 问题归集：对演练中暴露的技术短板、管理漏洞、流程断点进行归类，分析成因及潜在影响范围。
  4. 成效评估：对照预案目标与考核标准，客观评价演练目标达成度、流程合规度、处置有效度。
  5. 报告输出：汇总数据并撰写评估报告，给出可落地的整改与持续改进建议。

问题 2：评估报告应覆盖哪些核心版块？

  1. 演练概况：说明演练目的、时间地点、参演单位与人员构成、模拟事件场景。
  2. 组织与实施：描述演练流程、各阶段开展情况、指挥部调度与协同效率。
  3. 目标达成度：逐条核对预设目标，给出达成率与差距分析。
  4. 参演人员评价：按角色评估响应速度、操作规范性、团队协作水平。
  5. 问题清单：分类列出技术缺陷、流程缺失、管理不足及协调卡点。
  6. 改进建议：针对每个问题给出整改措施、责任分工与时限建议。
  7. 评估结论：总结演练总体表现，明确是否通过评估及后续跟进事项。

4. 网络安全应急响应技术 - Linux Web 应急取证

题目

  1. 攻击者成功访问目标站点页面的总次数。
  2. 攻击者利用 Webshell 的页面 URI。
  3. 信息收集脚本的 32 位小写 MD5。
  4. 管理员权限利用脚本文件的 32 位小写 MD5。

实测答案

问题答案备注
Q1 成功访问次数52攻击者 IP 10.20.125.64 的 HTTP 200 响应数
Q2 Webshell URI/dede/login.phpPOST 请求集中出现，文件内容含登录状态
Q3 信息收集脚本 MD5047221a55de17485c651c83c8a9db329/var/www/html/data/.ll.sh（LinEnum 类脚本）
Q4 权限利用脚本 MD56bcb27ecf27f5eeb5b3dc162dc721f5b/home/ubuntu18/tmp/gzip

关键命令

步骤 1：定位攻击者 IP 与成功访问次数

# 统计请求量最大的 IP
awk '{print $1}' /var/log/apache2/access.log | sort | uniq -c | sort -rn | head
# 统计 10.20.125.64 的 HTTP 200 次数
awk '$1=="10.20.125.64" && $9==200 {c++} END{print c}' /var/log/apache2/access.log
# 实测：52

步骤 2：定位 Webshell

# 查看攻击者 POST 请求
awk '$1=="10.20.125.64" && $6=="\"POST" {print $7}' /var/log/apache2/access.log | sort | uniq -c | sort -rn
# 实测集中 POST：/dede/login.php

步骤 3：查找信息收集脚本

# 按时间/名称查找可疑脚本
find /var/www/html /tmp /var/tmp /home -type f -name '*.sh' 2>/dev/null

# 实测发现 /var/www/html/data/.ll.sh（LinEnum 脚本，46631 字节）
md5sum /var/www/html/data/.ll.sh
# 047221a55de17485c651c83c8a9db329

步骤 4：查找权限提升利用脚本

# 查找 SUID 文件
find / -perm -4000 -type f 2>/dev/null
# 实测发现 /home/ubuntu18/tmp/bash
# 查看 /home/ubuntu18/tmp 目录
ls -la /home/ubuntu18/tmp/
# -rwsr-xr-x 1 root root       1113504 /home/ubuntu18/tmp/bash
# -rwxrwxr-x 1 ubuntu18 ubuntu18     85 /home/ubuntu18/tmp/gzip

cat /home/ubuntu18/tmp/gzip

5. 网络安全等级保护 - B · 医院 HIS 系统

题目

某市三甲医院 HIS 系统：

  • 业务信息泄露或损坏会对患者造成特别严重影响，对公共利益与社会秩序造成严重损害。
  • 系统服务中断会对患者获取医疗服务造成严重影响，对公共利益与社会秩序造成一般损害。

问题 1：判定该 HIS 系统的安全保护等级

  • 业务信息安全保护等级：第三级
  • 系统服务安全保护等级：第二级
  • 整体定级结果（按"就高不就低"原则）：第三级

问题 2：安全管理中心需具备哪些能力

① 系统管理维度

  • 系统管理员须经身份鉴别后，方可通过专用命令或操作台开展配置类操作，所有动作全程留痕审计；
  • 由系统管理员统一管控用户身份、资源配置、加载启动、异常处理、备份与恢复等运行事项。

② 安全管理维度

  • 安全管理员同样需通过身份鉴别，使用专用通道进行策略配置，并对自身操作进行审计；
  • 由安全管理员统一配置安全参数、主体/客体安全标记、访问授权及可信验证策略。

③ 集中管控维度

  1. 划定专门的管理区域，集中纳管分布在网络中的安全设备与组件；
  2. 建立专用的安全传输路径用于管控上述设备与组件；
  3. 对链路、安全设备、网络设备、服务器等运行状态进行集中监测；
  4. 汇聚各节点审计数据集中分析，并保证留存时间符合法律法规要求；
  5. 对安全策略、恶意代码库、补丁升级等事项进行集中管理与分发；
  6. 对网络中发生的安全事件进行识别、告警与关联分析。

问题 3：安全区域边界应落实哪些要求

① 边界防护（2 分）

  • 跨越边界的访问和数据流必须经由受控接口；
  • 能够检测并阻断非授权设备私接内网的行为；
  • 能够检测并阻断内网用户私自联外网的行为；
  • 无线网络须经受控边界设备才能接入内网。

② 访问控制（5 分）

  • 依据访问控制策略配置规则，默认拒绝、显式放行；
  • 定期清理无效规则，保持 ACL 最小化；
  • 对源/目的 IP、端口、协议进行五元组检查；
  • 结合会话状态提供精确的允许/拒绝能力；
  • 支持应用层协议与内容的访问控制。

③ 入侵防范（3 分）

  • 在关键节点部署检测手段，对内外双向的网络攻击进行阻断与限制；
  • 对网络行为做深度分析，覆盖已知和新型攻击手法；
  • 记录攻击源 IP、类型、目标、时间等日志，严重事件即时告警。

问题 4：安全运维管理有哪些必备要素

① 重要资产配置信息（2 分）

应建档保存：

  • 整体网络拓扑结构
  • 各设备安装的软件组件清单
  • 软件版本及补丁信息
  • 关键配置参数

② 安全事件报告与处置制度（2 分）

制度应明确：

  • 分级分类的安全事件报告、处置与响应流程；
  • 现场处置、信息上报、后期恢复的岗位职责与衔接关系。

③ 备份策略要求（3 分）

策略中应规定：

  • 备份方式（全量 / 增量 / 差异）
  • 备份频度（每日 / 每周 / 每月）
  • 存储介质（磁盘 / 磁带 / 云）
  • 保留期限（须满足法规与业务恢复目标）

问题 5：整改建议（按等保 2.0 逐条对标）

结合案例材料中 HIS 系统常见的薄弱环节，针对性提出整改措施：

① 安全管理中心方面

  • 设立独立的系统管理员、安全管理员、审计管理员"三员"岗位，明确职责分离与互斥监督；
  • 部署集中管控平台，统一纳管防火墙、堡垒机、数据库审计、终端 EDR 等安全组件；
  • 将日志统一接入 SOC / SIEM 平台，保留期不少于 6 个月，并配置关联分析与告警规则；
  • 建立补丁基线与版本基线，由集中管控平台统一下发安全补丁与恶意代码库升级。

② 安全区域边界方面

  • 按业务域划分安全区域，门诊、住院、办公、互联网接入区之间通过下一代防火墙隔离；
  • 梳理并收敛对外开放端口，严格按"白名单"模式配置 ACL，删除长期未用的无效规则；
  • 在互联网出口与核心交换机旁路部署 IPS，对 SQL 注入、Webshell 上传等行为实时阻断；
  • 关闭不必要的无线 AP，确需使用的统一通过准入网关接入，并强制 802.1X 认证。

③ 安全计算环境方面

  • 服务器与数据库开启强口令策略 + 多因素认证，禁止默认账号、共享账号；
  • 关键业务系统启用主机 EDR，应用最小权限原则与数据库行级访问控制；
  • 部署统一防病毒平台，启用主机防火墙与白名单机制；
  • 患者敏感数据（含姓名、身份证、病历）按等保要求加密存储与传输，关键字段脱敏展示。

④ 安全运维管理方面

  • 建立资产配置管理库（CMDB），动态记录拓扑、软件清单、版本补丁与配置基线；
  • 制定《安全事件报告与处置管理制度》，明确 5×8 / 7×24 值班与上报流程；
  • 核心 HIS 数据采用"本地全量 + 异地增量 + 云端快照"的三级备份策略，恢复演练每半年至少 1 次；
  • 引入等保测评与攻防演练（红蓝对抗）机制，每年开展 1 次等级测评与渗透测试。

解题套路小结

  1. 定级：结合"业务信息"与"系统服务"两条线分别判定，再按就高原则汇总。
  2. 安全管理中心：围绕系统管理、安全管理、集中管控三大块成体系作答。
  3. 安全区域边界：按边界防护 → 访问控制 → 入侵防范三段式展开。
  4. 安全运维管理：围绕资产配置、事件制度、备份要求三块做清单式回答。
  5. 整改建议：从管理中心、区域边界、计算环境、运维管理 4 个维度，对照等保 2.0 控制项逐条给出整改措施。

6. 培训实施与技术指导 - F · 培训大纲 + 考核方案

题目要求

  1. 结合国标二级"网络安全等级保护"工作内容，拟制一份培训大纲。
  2. 结合国标二级"网络安全等级保护"工作内容，拟制一份考核方案。

参考答案 1：网络安全等级保护培训大纲

一、总体说明

编制依据：参照《网络与信息安全管理员》国家职业技能标准（2020 版）对二级/技师的技能要求设计本次培训。

培训目标：帮助学员系统掌握等保定级、备案、测评、整改、运维全流程的知识点与实操技能。

核心模块：等保 2.0 控制项解读、定级方法论、差距分析思路、整改方案设计、等级测评流程。

预期收获：具备独立承接等保项目的能力，满足职业技能等级认定的考核要求。

二、培训安排

  • 参训对象：二级/技师方向学员
  • 培训时长：共 X 天，合计 X 学时
  • 培训场地：XXX 机房或多媒体教室
  • 组织形式：理论精讲 + 案例研讨 + 实操训练三位一体

三、课程模块清单

围绕国标二级"网络安全等级保护"工作要求：

  1. 等保制度演进与现行标准体系
  2. 信息系统定级方法与备案流程
  3. 安全物理环境控制项详解
  4. 安全通信网络设计与实现
  5. 安全区域边界的访问控制与防护
  6. 安全计算环境的合规要求
  7. 安全管理中心的建设思路
  8. 安全管理机构与管理制度
  9. 安全建设管理与安全运维管理
  10. 等级测评实施与整改复测要点

四、考核安排

  1. 成绩构成：理论考核 40% + 实操考核 60%
  2. 考核时间：培训结束后的第 X 天统一组织
  3. 考核方式：上机考试 + 案例分析 + 实操任务

五、培训资源保障

  1. 专用培训教室、多媒体教学设备
  2. 等保案例库、测评工具链与演练靶场
  3. 配套教材、PPT 讲义、实验操作手册
